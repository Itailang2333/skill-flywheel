# 硬强制三档：把"软执行"变成"不漏"

SKILL.md 是软执行：规则靠上下文里的指令"提醒"，Agent 可能漏（技能没被加载、被长任务挤掉注意力）。本文给出三档可叠加的加固手段，按宿主能力选用。全部思路来自作者内部环境的实跑验证，此处只讲通用做法，不含任何私有实现。

## 档〇（基线）：本仓库的 SKILL.md

无任何基础设施要求。局限：会漏。适合先跑起来观察漏率，再决定上哪几档。

## 档一：会话开场注入

**前提**：宿主支持 session-start 钩子（如 DSH 的 hooks）。

**做法**：
1. 把强制规则写成**独立的规则文本文件**（UTF-8 无 BOM），钩子只负责"读文件 → 注入会话"。规则与钩子分离，改规则不动代码。
2. 注入内容按"第 N 条"编号，方便其他规则引用（"按第 8 条…"）。
3. 长度预算：实测 ~1.5KB 的规则文本注入稳定可靠；规则越多越要克制，每条只留一句话能执行的配方。
4. **规则文本里禁止出现业务机密**——它会进每一个会话。

**通用规则集模板**（示例，按需增删）：

```
1) 沉淀触发：本轮 >=8 次工具调用且含 >=3 个可独立验证步骤，或修好棘手报错/环境坑，或发现非显然可复用流程 → 按沉淀规则执行。
2) 沉淀动作：同一轮内写 <技能根>/<kebab名>/SKILL.md；frontmatter：name=目录名、description 只写触发条件与触发词（禁止工作流摘要）、agent_created: true。
3) 落笔前查重：同岗位已有手册 → 并入既有 SKILL.md，禁止新建同岗位第二本。
4) 反思四问：用过的技能——过期？错误？缺步骤？措辞乱？发现问题先修订再回复；修订他人技能须在本体留痕（改动+原因+日期），不改名、不盖 agent_created 章。
5) 唯一豁免：一次性任务、含未脱敏敏感信息（改走 Memory）、已有同名 skill 完整覆盖。拿不准时倾向沉淀。
6) 报数必带实物指针：报告/回复里的每个数字注明出处（抄自哪个文件哪一行/哪条命令原样输出）；数不出指针的一律写「异常」，禁止凭印象报数。
```

> 第 6 条是实战教训的产物：Agent 在"写宣传文案"模式下最容易编造战果数字。它对所有报数场景通用。

## 档二：运行时刹车

**前提**：宿主支持工具调用的插件/中间件拦截（如 DSH 的 profile 插件）。

**做法**（通用逻辑，伪代码级）：

```
on each tool call:
    turns_counter += 1
    if args mentions "SKILL.md":
        skill_touched = true
    if turns_counter >= 8 and not skill_touched and not reminded_this_turn:
        inject_user_message("【沉淀强制】本轮已完成 N 次工具调用且尚未沉淀可复用方法。"
                            "请按 skill-accumulation 规则自查：有无可沉淀流程？"
                            "无则说明豁免理由再收尾。")
        reminded_this_turn = true
on new turn:
    turns_counter = 0; reminded_this_turn = false
```

**要点**：
- 只**提醒不阻断**——注入一条用户消息把注意力拉回来，不 kill 会话。
- 同一轮只提醒一次，避免骚扰。
- 检测"SKILL.md 触碰"看的是工具调用参数里的路径/文件名，实现各自宿主而定。
- 实测效果：长任务中途（11 次调用无沉淀）被刹车拉回后，Agent 当场完成了一次合格沉淀。

## 档三：定时兜底

**前提**：宿主支持 cron/interval 自动化或会话结束钩子。

直接用 [`watchdog-automation.md`](../watchdog-automation.md) 的注册提示词：守护进程定期回看近 N 轮对话，命中触发规则的补沉淀。与档一二不冲突——它接住前面两档漏掉的。

## 三档关系

| 档 | 管什么 | 失效场景 |
|---|---|---|
| 一 | 开场在场 | 会话超长把规则挤出注意力 |
| 二 | 中途拉回 | 无插件能力的宿主 |
| 三 | 事后兜底 | 无 cron 能力的宿主 |

三档叠加 = 开场必见 + 中途拉回 + 事后兜底，接近平台强制层的"不漏"。

## 两个实证坑（命名与写法）

1. **技能/探针命名只用字母、数字、连字符，且字母开头**——下划线/特殊字符开头会被 DSH 技能加载器拒识（`invalid skill name`），注入的探针无声失效、白跑一轮。
2. **规则文本里写 description 纪律时，自己也别犯**——任何"description 里写工作流摘要"的示例都会诱导模型模仿。示例一律用 SDO 写法。
